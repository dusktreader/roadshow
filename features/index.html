Features

Roadshow turns tagged Python functions into demos that can be discovered, run, captured, and rendered.

Tag demos and build a CLI

Mark each demo with one feature name. Roadshow groups tagged functions by feature and displays each function's docstring with its source and output.

"""
Demonstrate how Roadshow groups demos by the feature they are showing off.

Note:
    Since this demo is not a part of a package, we need to use `get_standalone_module()`.
    For demos that are part of a package, just pass the package name as the first arg to `Roadshow()` or use the special
    `__package__` variable.

"""
from roadshow import Roadshow, demo, get_standalone_module


@demo("First Feature")
def feature_1_1():
    """This function demonstrates the first aspect of feature 1."""
    print("Look at how cool feature 1 is!")

@demo("First Feature")
def feature_1_2():
    """This function demonstrates the second aspect of feature 1."""
    print("Look at what else feature 1 can do!")


@demo("Second Feature")
def feature_2_1():
    """This function demonstrates the first aspect of feature 2."""
    print("Look at how cool feature 2 is!")

@demo("Second Feature")
def feature_2_2():
    """This function demonstrates the second aspect of feature 2."""
    print("Look at what else feature 2 can do!")


if __name__ == "__main__":
    Roadshow(get_standalone_module(), title="examples").run()

Create an entrypoint that scans the package and starts the CLI:

from roadshow import Roadshow


def main() -> None:
    Roadshow("my_app", title="My app").run()


if __name__ == "__main__":
    main()

Select one or more feature groups with --feature; repeat the option to select multiple groups. Omit it to run every group. By default, Roadshow asks for confirmation before starting and after each demo. --non-interactive skips those prompts, runs all selected demos, and exits with status 1 if any demo fails. Roadshow displays a failure and continues to the next demo unless the user stops an interactive run.

Discover demos in modules and packages

discover_demos(module) returns tagged functions defined directly in that module. Roadshow(package).discover() imports a package and its submodules, then returns demos grouped by feature. Package discovery imports every submodule, so their module-level code runs during discovery.

from my_app import demos
from roadshow import Roadshow, discover_demos

module_demos = discover_demos(demos)
package_demos = Roadshow("my_app").discover()

Use Roadshow(get_standalone_module()).run() to discover demos in a directly executed script that is not an importable package. The helper supplies the current __main__ module in the same position as a package name.

Supply input and arguments

Set input_text and argv on the decorator to give a demo predictable standard input and command-line arguments. The first sys.argv value is the demo function name.

"""
Demonstrate how Roadshow can supply cli args and input to a demo function.

Note:
    Since this demo is not a part of a package, we need to use `get_standalone_module()`.
    For demos that are part of a package, just pass the package name as the first arg to `Roadshow()` or use the special
    `__package__` variable.

"""
import sys

from roadshow import Roadshow, demo, get_standalone_module


@demo("Input Helpers", input_text="Ada\n", argv=("--formal",))
def input_helpers():
    """This demo shows how Roadshow can set stdin and argv for a demo function."""
    print(f"Hello, {input()}.")
    print(sys.argv[1:])


if __name__ == "__main__":
    Roadshow(get_standalone_module(), title="examples").run()

The demo reads Ada from input() and sees ("--formal",) in sys.argv[1:]. Explicit input_text or argv arguments to capture_demo() and display_demo() override the decorator fixtures.

Run setup and cleanup hooks

Pass zero-argument callables as before and after. Roadshow captures their output along with the demo output. It runs before before home isolation. With isolation enabled, it runs after in a finally block after restoring the caller's HOME and XDG values. The cleanup hook still runs if setup or the demo raises.

"""
Demonstrate how Roadshow can use the `before` and `after` lifecycle hooks around a demo function.

Note:
    Since this demo is not a part of a package, we need to use `get_standalone_module()`.
    For demos that are part of a package, just pass the package name as the first arg to `Roadshow()` or use the special
    `__package__` variable.

"""
from roadshow import Roadshow, demo, get_standalone_module


def announce_start():
    print("Before the demo function")


def announce_finish():
    print("After the demo function")


@demo("Lifecycle Hooks", before=announce_start, after=announce_finish)
def before_and_after():
    """This function shows how Roadshow runs `before` and `after` lifecycle hooks around a demo function."""
    print("Inside the demo function")


if __name__ == "__main__":
    Roadshow(get_standalone_module(), title="examples").run()

Capture execution results

Use capture_demo() to run a demo without rendering it. The result contains captured stdout and stderr, and records an exception or exit code when one occurs. Check succeeded to determine whether it completed successfully.

from roadshow import capture_demo


def show_report():
    print("Three records found.")


result = capture_demo(show_report)
print(result.stdout or "", end="")
if not result.succeeded:
    print(result.error or result.exit_code)

Capture redirects standard input, output, and error. It records ordinary exceptions in error and SystemExit in exit_code. By default, it temporarily points HOME and the XDG cache, config, and state directories at a temporary home, then restores the caller's environment. Pass isolate_home=False to retain the existing home and environment. Capture runs code in the current process; it is not a sandbox, does not undo arbitrary side effects, and should not run concurrently from multiple threads.

Inspect and render demos

decompose_demo() returns a DemoDetails value with a demo's module, name, docstring, and source. The source includes the function signature and executable body. If a demo has no docstring, Roadshow uses function_name() demo as its description.

from rich.console import Console
from roadshow import decompose_demo, demo
from roadshow.render import display_demo


@demo("reports")
def show_report():
    """Print a report summary."""
    print("Three records found.")


details = decompose_demo(show_report)
print(details.source)
display_demo(show_report, Console())

display_demo() runs and captures the demo before rendering its documentation, source, output, errors, and exit status.

Raise application errors

RoadshowError derives from buzz.Buzz. Use it or its Buzz validation methods when a demo needs to report invalid setup:

"""
Demonstrate how Roadshow will capture exceptions raised in a demo function.

Note:
    Since this demo is not a part of a package, we need to use `get_standalone_module()`.
    For demos that are part of a package, just pass the package name as the first arg to `Roadshow()` or use the special
    `__package__` variable.

"""
from roadshow import Roadshow, demo, get_standalone_module


@demo("Error Handling")
def explode():
    """This function shows how Roadshow captures exceptions raised from a demo function."""
    print("Now we'll raise an error that Roadshow will capture and display")
    raise RuntimeError("Boom!")


if __name__ == "__main__":
    Roadshow(get_standalone_module(), title="examples").run()
